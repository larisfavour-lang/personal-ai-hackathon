# 随身助手：个人助理 → 浏览器助手

本目录是黑客松作品的浏览器插件部分，名字是「随身助手」。它做三件事：

一是接着办个人助理里的事。同一件事换到别的页面继续挑，预算、用途、
相关偏好、排除项和还没定的条件都从应用里带过来，不用重说一遍；
要拿到别的平台去问人时，可以复制搜索词和需求说明。

二是读当前这一页的内容。在事项行点「读这一页」，当前页面的标题、
正文、表格、控件说明和按钮文字就取回来摊在面板上，可以复制。
页面里说不清、要带回去接着办的内容，不用自己一段段抄。

三是在支持的页面上代填。把这次要填的参数先摊给本人看，本人确认后
才写进页面控件，再回读页面实际值核对，回执存回应用里的同一事项。

三件事都不提交订单、不付款、不读取账号密码，也不自动往任何网页或
别人的助手发消息。复制和代填都由用户主动点。

产品基准（设计文档，按名引用）：`friday-delivery-plan.md`（产品计划）
与 `app-extension-integration-spec.md`（插件契约）。本目录只负责插件侧；
服务端接口、数据库、手机入口由主服务仓库负责。

## 目录

```
manifest.json                MV3 清单（host 权限：127.0.0.1:8000/8097/9000/8098）
src/lib/contract.js          契约 v1：字段白名单、参数包校验、字段比对
src/lib/config.js            核心服务地址（唯一入口）
src/lib/api.js               后台专用客户端，凭证只在这里流转
src/lib/clipboard.js         复制到剪贴板（先展示内容，再按用户点击复制）
src/background/service-worker.js  后台：唯一与核心服务对话的进程
src/content/shop-adapter.js  页面适配器：只填白名单字段、读回真实控件值
src/content/page-reader.js   页面内容读取器：只读页面显示的文字，不读表单已填值
src/popup/                   用户唯一界面：配对、预览、确认代填、回执
fixtures/mock-shop/          独立模拟商店（真实控件与页面业务状态）
fixtures/contract-stub-server.py  契约替身，仅开发联调用（fixture）
test/contract.test.js        契约单元测试（Node，无网络）
test/api-renewal.test.js     凭证静默轮换回归测试（Node，无网络）
docs/README.md               本文件
```

站点适配器现在只有 `src/content/shop-adapter.js` 一个（模拟商店），
没有独立的 `adapters/` 目录；换站点时在这里加，不动后台与契约。

## 安装（用户视角，约 1 分钟）

1. 打开 Chrome，地址栏输入 `chrome://extensions`。
2. 右上角打开「开发者模式」。
3. 点「加载已解压的扩展程序」，选择本目录 `extensions/context-bridge/`。
4. 工具栏出现拼图图标，固定住随身助手即可。

连接（只做一次，两端互指）：

1. 在个人助理页面点右上角「⋯」（演示设置）→「浏览器插件」→ 点「连接浏览器插件」
   生成配对码（8 位，5 分钟内有效、限一次）。应用会提示：点 Chrome 工具栏上的
   「随身助手」图标，在弹出的窗口里输入这个码。
2. 点插件图标，在配对视图填配对码和设备名称（例如「我的电脑 Chrome」，
   用于在应用里认这台电脑、随时撤销），点「连接」。插件配对视图里也写明
   码从哪来：个人助理 → 演示设置 → 浏览器插件 → 连接浏览器插件。
3. 连上后插件标题下显示「已连接：<设备名>（<归属人>）」——说得清连的是哪台设备；
   应用里可以随时撤销这个设备，插件里的「断开这个设备」同样可撤销。

这台电脑加入的是你本人的助手：之后你在手机上交办的事，由这台电脑上的插件
去执行，回执回到同一件事里；不是手机和插件互相配对，手机也不需要装任何东西。

连上之后长期有效：关掉 Chrome 再打开、换商品页、换网站，都还是同一个人，
不需要重新配对。需要再连一次的情况：在应用里撤销了这个设备、清理了浏览器
数据、或在应用里点了「重置演示资料」（重置会清掉已配对设备，需重新配对）。
凭证存在扩展自己的持久存储里，并限制为
TRUSTED_CONTEXTS，商店页面的脚本读不到。

「确认并代填」那一次仍需要本人主动点：连接只是让插件认得你，
不代替你对每一次代填的确认。

## 使用

两件事，按要不要往页面里写来分。

换页面继续办同一件事（不用重新交代背景）：

1. 点插件图标，选一个本人事项。整行进需求卡。
2. 需求卡列出这次已知的预算、用途、偏好、排除项，每项带来源和确认时间；
   还没定的条件单独列在下面，不冒充确定规格。
3. 要换到别的页面继续挑，点「复制搜索词」或「复制这次需求」，粘到那边用。
   两份内容在打开时就摊在界面上，复制前会重新取一次最新版本——
   有变化时这次不复制，先把差异摊开给你核对，你再次点才复制。
4. 插件不自动往任何网页、客服或别人的助手发消息，复制全由你主动点。

读当前这一页的内容（看到说不清、要带回去接着办的东西时用）：

1. 先在要读的那个页面上点一下，再打开插件。
2. 点插件图标，在事项行点「读这一页」。
3. 面板列出这一页的标题、地址和正文，逐段摊开。
4. 要带走就点「复制这一页内容」；页面变了点「重新读一次」。

读取范围只说清三件事：只看得到的正文、标题、表格和控件说明；
输入框里已经填的值一律不读；密码控件整块跳过。display:none、
aria-hidden、折叠起来的内容不读，并在界面说明有几处没收。
读取过程不改页面任何状态，也不发起网络请求。

在支持的页面代填（要写页面控件时才用）：

1. 打开支持代填的商品页（当前是随附的模拟商店）。
2. 点插件图标，在事项行点「去代填」。
3. 插件列出这次要填的字段、值和来源，先预览。
4. 确认无误点「确认并代填」。插件只写页面控件，不点提交订单。
5. 页面回读实际值与业务状态，回执保存到应用里的同一事项。

需求卡不看协商有没有谈成：还没定的事也能看已知部分、复制搜索词和需求说明，
只是不能代填。执行资格仍由预览、实时校验和你的确认三道把关。

## 随包测试（无网络、不连真实服务）

在本目录（`extensions/context-bridge/`）下跑：

```
node --test test/contract.test.js test/api-renewal.test.js
```

契约单元测试（Node，无网络）：字段白名单、参数包校验、字段比对逻辑；
凭证静默轮换回归（服务端轮换设备凭证后旧凭证失效，插件读响应头续接）。

`fixtures/contract-stub-server.py` 是开发期契约替身（fixture），用于在没有
真实服务时联调插件行为；它只证明插件自己的逻辑，**不代表真实服务行为**。
应用侧（主服务）的测试套件在主仓库 `tests/` 下，不属本目录范围。

## 验证状态（如实）

完整多层验证（真实 Chrome 全链、真实主服务联调、安全负验）的结论与边界
见交付材料中的验证摘要：[../../../docs/delivery/verification-summary.md](../../../docs/delivery/verification-summary.md)
（原始日志不随本包分发；本 README 不重复验收记录）。当前已确认的事实：

- 契约单测 38/38（Node，无网络）；guard 反例套件 28/28（Python，隔离临时库）。
- HTTP 契约核对：14 PASS + 1 数据性 GAP——t27 隔离实例里没有可协商的购物事项
  （缺 shopping fixture，即 prepare/需求卡的数据前置），需求卡无事项可读；
  属测试数据前置缺失，**不是**「context 无事项时返回空」的接口行为，也不是契约破坏。
- 完整浏览器链（配对→列事项→预览→服务端校验→代填→页面控件真实读回→
  回执→应用侧读回→关页拒绝）曾在一个基线版本上跑通 73/73：2026-10-16 于代码
  基线 d45bb5d、隔离服务+隔离库+随附模拟商店、开发副本（manifest 临时加 8391
  host 权限）上完成。此后的家庭主线修复经 diff 审计确认插件面零改动，**未对该
  全链做本轮完整重跑**。该结果证明插件与真实服务之间的链路成立，
  **不是真店下单、不付款、无真实交易**；当前状态以验证摘要与 diff 审计为准。
- 家庭主线修复（t25/t26）对插件面零改动：9 个 `/api/extension/*` 路由、
  设备凭证校验、参数包/回执契约 diff 为 0 行；受邀 guest 会话访问扩展路由
  一律 403，家庭活动（plan）不进入购物插件清单。

## 已知边界

- 需求卡依赖 `POST /api/extension/context`。该接口在主服务上已上线；
  接口不在时插件会明确说「服务端还没有这个接口」，不显示空白卡片，
  也不把失败当成功。
- 复制能力只写剪贴板，不自动向任何网页、客服或别人的助手发消息；
  换页面后仍要用户自己粘贴。这不等于已适配真实电商、自动选品或自动下单。
  用户机器上写不进去时插件明确说「没能自动复制，请手动选择下面内容」，
  不假装成功。
- 只有一个适配器（模拟商店）。淘宝、京东、拼多多未验证，买票与预订网站未做。
- 适配器只处理契约白名单里的字段，且页面没有对应控件时报「没有这个字段的控件」，
  不静默跳过：参数包带了电话而页面没有电话输入框时，回执会记 partial 而不是 filled。
- 商品编号是页面的只读控件。插件只核对它和参数包是否一致，不改写；
  不一致时代填被拒绝，不伪造商品。
- 代填停在供本人核对的页面，不提交订单、不付款、不做真实交易；
  回执经 API 存回应用侧同一事项——**API 回执可见不等于安卓真机上的界面验证**，
  安卓真机验收由用户本人执行。
- 凭证保存在扩展 `chrome.storage.local` 并限制为 TRUSTED_CONTEXTS，
  页面脚本读不到；旧的 `chrome.storage.session` 会话会在读取时整批迁入持久存储
  并清空 session，撤销后两处都清、不会被残留数据复活。公开部署的真实账号体系
  尚未实现，当前是本地单用户演示。
- 当前窗口同时打开多个商品页且没有明确激活项时，插件要求用户先点一下目标页，
  不猜、不自动选第一个。
- 端口与权限：manifest 的 host 权限覆盖 `127.0.0.1:8000/8097/9000/8098`。
  把插件指向其他端口（如开发副本指向 8391）时，必须在**该副本**的 manifest 里
  加上对应 origin；仓库 manifest 不做此改动。普通用户请直接连 8000 主服务，
  不要按开发者文档里的隔离端口操作。
- 家庭事项与购物事项分开：多人家庭活动走 plan 链，不进本插件的代填清单；
  受邀（自称）参与者只有事项限定会话，访问扩展接口一律被拒。
- 服务端语音转写当前不可用（已实测），语音输入请用浏览器自带识别或输入法，
  详见验证摘要；这不影响本插件的文字与图片链路。
