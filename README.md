# 我的小助手：记得身边人的情况，与人办事少协调

个人 AI 黑客松作品。

一个人的情况要跟不同的人反复讲。跟老师说孩子这周练了多久琴，跟另一个家长再讲一遍；跟同事交代过的背景，换个项目从头再说；给朋友帮过忙，下次他换了个人对接，你还得再讲一次。过两周自己也要重新回忆。

几个人约一件事，没有版本。群里接龙，有人说了周六可以，后来改成周六上午，之前那句“可以”还作不作数只能靠记忆。约旅行、排值班、合伙做点什么都一样。

办一件事要查历史。上次送了什么、穿多大码、地址填的哪个、跟对方谈到哪一步，散在聊天记录、相册和收藏夹里，用的时候靠翻。

我做的是个助理：事情在一个地方交办，它接着办。演示主线是家庭活动，另外覆盖送礼、朋友旅行和跨页面采购。

里面有手机优先的对话页、资料库、小应用（学习软件／周末安排／送礼管家／数据接入／关系分类），还有一个 Chrome 插件。送礼和商店代填是另外的模拟用例，跟家庭活动不是一回事。

## 定位与方案

定位是个人 AI 的能力底座：支撑跨应用记忆复用和跨用户协商办事。核心规则只有一条，知道一个人的情况，不等于可以把他的信息说出去。所以资料、授权、方案版本、回应、执行状态分别记录；模型负责读图、抽信息、提方案，身份、授权、预算和版本一致性由程序校验。

当前形态是手机优先的 Web 演示，桌面 Chrome 插件作为电脑端的执行手。Web 只是演示载体，不是最终形态。

同一个底座还能长成另外两种样子。一种是给现有 Agent 调用的能力：通过适配接口读取和修正有效的人物信息、发起协商、查询执行结果。另一种是承载独立的 PA：有自己的交互入口、事项管理，以及在明确授权下的事件续办。三种形态共用核心状态与业务规则，不以前端技术决定产品方向。

除当前这一种，另外两种都没有实现，也没有被任何外部 Agent 或平台接入。人物关系、来源与时效、应用读取范围、个人代表权限和事项版本由共同底座持有，各应用提供适合自己任务的界面。

## 当前形态

产品定位是个人 AI 的能力底座：支撑跨应用记忆复用和跨用户协商办事，不是由某个前端形态定义的。人物关系、来源与时效、应用读取范围、个人代表权限和事项版本由共同底座持有；记忆持久存在，各应用提供适合自己任务的界面。

当前只交付其中一种形态的一个切片：一个独立的 PA——手机优先的 Web 演示，加上桌面 Chrome 插件作为电脑端的执行手。其它形态没有实现，也没有被任何外部 Agent 或平台接入。下面写的运行方式、手机访问和插件，都是这个切片的形态，不是产品定位本身。

## 特色功能

**图先落草稿，送不送你说了算。** 选完图，图先进草稿、缩略图马上能看见，这时候一次都没送出去。弹层里再挑：识别文字进正文、只存图不识别、还是先裁剪再识别。不存在“先传整张、再说边缘没上传”这种事。

**私有来源和对外可见是两件事。** 资料先私有关联到事项，默认一个字段都不选；要别家看见什么，得你逐条挑已经核对过的短字段原值、再确认一次。正文和图片不会自动共享。

**代表审阅不算本人同意。** 模型可以以你的名义先看一版方案，但那只是建议。只有你本人对当前这一版点了头才算数；发起人也填不了别家的条件。

**同一个版本才计数，条件变了旧同意作废。** 改一个时间或出资上限，旧的接受立刻失效，要重排新版、各方重新表态。接受的是旧版本不能算约定。

**再次采用要能证明。** 方案里可以说“用了新值”，但服务器当前版本的出处必须真的指向你改过之后重新选中的那个字段，否则不算采用。

**随行说不说由你定，代决策单独记账。** 加入共同事项时，你可以只报人数，也可以说出随行是谁；说了名字的随行进事项。没配自己助手的随行者，默认由声明的参与者代他决策——代决策是单独一类记录，不计入“已约定”，也不和代表审阅混为一谈。

**同一套引擎换场景。** 事项的条件字段按场景配置：家庭活动一套，朋友旅行一套，互不串味。学习软件、周末安排、送礼管家、数据接入都共用同一份记录和状态。

自己开发的应用和设备都能接进来。学习软件接进来，家长在一个对话里就看到孩子这周进展，不用在几个 App 之间切。给妈妈做的用药提醒应用、她戴的智能手表接进来，你问血压怎么样、药有没有按时吃，它答的是这些应用和设备里的数据，她本人不用装你的助理。智能手表这类设备当前还是预留位，标着建设中，接入前不读取任何数据。

**未授权的数据进不了模型。** 送礼档案、连接器导入的记录，都按字段授权；没授权的条目连提示词里都不会出现，这一点有测试直接断言，不是口头承诺。

## 本地运行

需要 Python 3.10+ 和一个 OpenAI 兼容的模型接口。下面是在 macOS／Linux 用守护方式启动，Windows 请按[运行指南](<docs/run-standalone.md>)用前台入口。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
PA_MODEL_BASE_URL="https://你的模型接口/v1" \
PA_MODEL_NAME="你的模型名" \
PA_MODEL_API_KEY="你的密钥" \
python start_server.py 8000
```

本机已经有代理的话，直接 `python start_server.py 8000` 就行。默认接口是 `http://127.0.0.1:10100/v1`，默认模型标签是 `step/step-5-preview`。这个代理不随源码分发，换一台电脑不能照抄这个地址就假定模型可用。

电脑打开 `http://127.0.0.1:8000`。手机要在同一局域网，扫首页「⋯ → 演示设置 → 手机访问 → 在手机上打开」里的二维码，电脑得保持开机。手机上的 `127.0.0.1` 指的是手机自己，访问不到电脑。

服务默认监听 `0.0.0.0`，只本机用就设 `PA_BIND=127.0.0.1`。局域网不是公网体验地址，也没有公开注册登录。相机、麦克风和安装到主屏能不能用，由浏览器决定。

普通用户用已经启动好的服务就行，不用配模型，也不用切换身份。密钥存在本地运行库里，不要随源码分享。

## 从一件家庭事项开始

几个家庭一起办事，各人把自己的情况说一次就存下。约家庭聚会、几家一起出游、合伙做点什么都行：时间、预算、孩子来不来，各家补一次；之后助理记着，你这边随时看得到还差谁、差什么，不用挨个问。

改了时间或预算，只有受影响的约定要重新确认，别家不用把话再讲一遍。每个方案有版本，谁点了头记在哪个版本上；本人没点头就不算约定，也不拿没确认的人凑数。

1. 说「周末三家一起带孩子出去玩，我出100以内」，在回复里打开同一件事。100 元是你自己最多愿意出的钱，不是活动总预算，也不是答应了要付。
2. 看看当前知道的情况：有哪些家庭、哪些孩子、什么还没确认。演示里的 A／B／C 是三个身份，B 小周和 C 小林同户，其实是两个家庭。第三家不知道就留着缺口，不把配偶算成第三家。
3. 按现在有的条件排候选。只有真正参与的人接受同一个版本，才算约定下来；模型代表的审阅和本人点确认是两回事，没回应就是还没确认。
4. 改自己的时间、出资上限这些条件，然后重新排一版。旧的接受跟着失效，历史记录还在。失败了会告诉你为什么，可以重试。

想请别的家庭参与，从事项里「邀请另一个家庭参与 → 生成单次邀请」拿一条专用链接。对方在自己浏览器里打开、自称是谁、只填自己的条件和孩子的名单；你「认可自称家庭」之后，才按所有人当前的条件重排一个新版本，再由他本人对这一版表态。他不能直接接受旧版。代表审阅只是建议，本人接受才算。链接不代表实名，也不会套用 B／C 的资料。

名单上有几个孩子，不等于这几个孩子都来。来的、不来的、待定的分别记。

资料保存后选「用于家庭活动」，默认一个字段都不选。先关联你私人的来源，再挑已经核对过的短字段原值，确认别家可见才公开。正文和图片不会自动共享。改了或撤了之后，旧接受失效，要重新选、重新公开、重新排，并且以服务器当前的出处证明新值真的被用上了。

## 录入、核对与再次使用

从「☰ → 资料库 → 添加资料」进去。「记什么」那个框打开就能写，不用先拍照也不用先选人。

- **图片识别**：点了这一级选项再选一张本地图。图先进草稿，缩略图马上能看见，这时候还没送出去。弹层里再挑：
  - 「识别图里的文字，进正文框」——只有点这一下，图才送去做识别。文字加在原正文后面，中间换行，你已经写的字不动。
  - 「只把图存进资料库，不识别」——一次模型都不调，图只作为配图跟着记录存。
  - 「先裁剪再识别」（次级）——只有框住的那块送识别，取消裁剪就不调。不存在先送完整图、再说边缘没上传这种事。
- **语音输入**：用浏览器自带的语音识别，在浏览器里完成，不送服务端。浏览器不支持或者不让用麦克风的时候，它会直说。
- 核对错字、对象和发生日期之后再保存，再打开记录看看正文、来源和配图对不对。
- 识别失败会说原因，图和你的正文都留着，可以改、可以重试、可以放着以后再来。模型返回空白不算识别成功。取消草稿不会多出一条记录。

存的时候选记在谁名下，之后能关联到某件事——给别家看什么你逐条挑，默认一条都不给。下次问“小雨这周数学练得怎么样”，助手拿你存的那条回答，带得出是哪天、谁记的、依据是什么。

保存资料本身不等于同意对外分享、答应别人什么事或者去执行。要用在哪件事上，得你自己选，再按对象、用途和授权筛。只是存了、没被采用的内容，不能写成「这次的依据」。资料的发生日期和活动的日期是两回事，分别核对。

学习记录和周末安排这两个视图用的是作品内的测试数据，不是接进了真实的学校软件、微信或手表。

## Chrome 插件：换页面少重说

插件跑在桌面 Chrome/Edge 上：电脑 Chrome 打开 `chrome://extensions`，开开发者模式，加载[插件目录](<extensions/context-bridge>)。插件叫「随身助手」，是你在电脑上代替操作页面的那双手，只按你授权的字段代填已批准的商店页面，不提交订单、不付款。加入一次长期有效：重开浏览器、换页面都保持着，只有在演示设置里撤销这台设备才失效。Android 上的 Chrome 不支持安装扩展，手机不能安装也不能配对；手机上能看到的是同一事项的代填回执。

要看代填，先另开一个终端起内置的模拟商店：

```bash
python -m http.server 9000 --bind 127.0.0.1 \
  --directory extensions/context-bridge/fixtures/mock-shop
```

1. 在主应用「⋯ → 演示设置 → 浏览器插件」拿配对码，到插件里连上自己的服务。
2. 选自己的购物事项，看这次的需求、来源、还没确认的项，可以复制需求说明。换页面继续同一件事，改过了就重新取当前参数。
3. 在支持的模拟商店页面预览参数，你确认后代填。插件会把页面实际值读回来，主应用里同一事项能看到回执（手机上也是打开同一件事看这份回执）。
4. 回执只说明页面被填了、复核结果如何。插件不提交订单、不付款。没适配的网页就复制需求、自己动手，别说成已经代填了真实电商。

插件固定只访问本机 8000／8097／9000／8098，不是随便什么手机浏览器都能装。Android 的 Chrome 不支持安装扩展：手机不能安装插件、也不能加入，别在手机上点「把这台电脑加入助手」——那个入口在窄屏下不显示，能看到的是同一事项的代填回执。手机和这台电脑连的是同一个助手：你在手机上交办的事，由这台电脑上的插件去执行，回执回到同一件事里；不是手机和插件互相配对。家庭活动的计划不会进只给购物用的参数包。重置演示资料会清掉插件设备和配对，连过的要重连；平时别重置。

## 安全与数据说明

模型管抽取、提案、审阅、读图、提建议；程序管身份、授权、预算依据、品类规格和同版本接受。过期的、跨事项的、没确认的方案都不能拿去执行。误点确认也不该留下接受、约定或者订单的痕迹。

演示里的人物、关系、商品都是编的，购买、支付、物流全是 `simulated`，没有真实交易。文字和你选定识别的图会送到运行者配的模型服务；看附件的权限和给模型处理用的授权是两套检查。请只用不敏感的编造数据演示。

## 验证到哪一步

这个版本实际跑过的：

- 家庭主线跑完 14 步，全程真实模型：拍图识字进正文、改错字、按改过的来源重排方案、发一次性邀请、来宾自称并补条件、发起人认可、双方各自对当前版本点了头。最后没有全员约定，就写的没有全员约定。
- 三方协商跑通一轮真实模型，包含改条件后重排、旧的接受失效。
- 插件契约、接口该拒绝的路径、资料关联链，在隔离环境里全过。
- 安卓真机跑过：相机实拍、手指裁剪、真麦克风、重开继续、手机同事项回执，由用户本人在自己设备上验过。
- 送礼档案、朋友旅行、关系分类、连接器各自有离线测试；未授权的条目不进提示词这条有断言直接验。
- 演示视频 3 分 26.0 秒，1280×960，无音轨，真实屏幕采集帧重剪。等模型的时间剪短了，片里标了实际等了多少秒；不是一镜到底。
演示视频没有覆盖的三处，在仓库文档里可查：送礼协商（我提出／对方接受／模拟订单已登记）、演示设置面板（模型连接／手机访问／加入这台电脑／预留设备）、连接器配置面板（服务商地址／路径／字段映射）。这三处在产品里都能操作，视频时长有限未拍。

没跑的：

- 服务端语音转写不可用，26 次请求逐条试过，原因见下面。改用浏览器自带识别，或者输入法语音转文字后粘贴；后者不算内置语音识别做完了。
- 完整 22 项模型测试没有复跑。另一台电脑的干净安装也没验。

历史基线和以前的失败记录见[验收记录](<docs/acceptance-record.md>)。不要把 2026-10-15 的 22/22 当成当前全量通过。

源码里带了八个测试文件和两个 Node 单测（共 42 条用例），跑法见[运行指南](<docs/run-standalone.md#测试不是日常启动命令>)。工程里还有一些历史脚本硬编码 8000、写固定临时文件或者直接动运行库，别在日常实例上批量跑；真实模型测试要花钱。

源码只对启动管理器的一行模块 docstring 做了泛化，运行逻辑没动，其余文件按原字节选。ZIP 和公开快照是同一套分发字节，逐文件的原／分发 SHA-256 记在独立的交付映射里。

## 语音与其他边界

服务端语音转写不可用，26 次请求的记录在[语音核查摘要](<docs/delivery/verification-summary.md>)。四种死法都试过：带前缀的 `step/stepaudio-2.5-asr` 返回 404 `model_invalid`；去掉前缀返回 502 `Provider unreachable`；OpenAI 标准的 `/v1/audio/transcriptions` 端点不存在；音频 chat 模型能连通，但它把音频当对话接话，不吐转写。

「说一段」走浏览器自带的 SpeechRecognition，不经过本作品服务端。浏览器可能用它自己的识别服务，受设备、权限和安全上下文限制。自动化只验了接线通不通，真麦克风还没实测。

Step 的证据到配置标签和能核对的实际调用范围为止，不给百分比，也没有直接上游原始响应的捕获。真实电商、群消息发送、外部 Agent 接力、语义检索、公开多用户认证都没做。硬件加分资格不猜。
