# 我的小助手：记得身边人的情况，与人办事少协调

面向承担孩子学校、活动和家庭安排的人。把本次文字或图片交给助理，在同一件家庭事项中继续核实和准备，换个应用不必重新交代整件事。涉及别人时，各家只补自己的条件、授权自己的资料，对当前这一版本本人表态；代表审阅不算本人接受，条件变了旧表态失效，按新条件重排。

## 定位与当前形态

产品定位是个人 AI 的能力底座：支撑跨应用记忆复用和跨用户协商办事，不由当前前端形态定义。人物关系、来源与时效、应用读取范围、个人代表权限和事项版本由共同底座持有；记忆持久存在，各应用提供适合自己任务的界面。

同一个底座有两种未来形态：一种是作为现有 Agent 调用的能力，通过适配接口读取／修正有效人物信息、发起协商、查询执行结果；另一种是承载独立的 PA，有自己的交互入口、事项管理和在明确授权下的事件续办。两种形态共用核心状态与业务规则，不以前端技术决定产品方向。

当前只交付其中一种形态的一个切片：独立 PA 形态下的手机优先 Web 演示，桌面 Chrome 插件作为电脑端的执行手。其它形态没有实现，也没有被任何外部 Agent 或平台接入。

## 怎么用

打开手机优先的网页即可对话。说「周末三家一起带孩子出去玩，我出100以内」，进入家庭事项，查看当前条件与缺口，排候选方案；改自己的条件后继续新版本。100 元是本人出资上限，不是活动总预算或付款承诺。

资料库可以先写正文；要插图就点一级选项「图片识别」，选定本地文件后图先进草稿、尚未送出，再由本人选「识别图里的文字，进正文框」（只有点过才送模型）或「只把图存进资料库，不识别」（一次都不送），「先裁剪再识别」为次级选项。也可以用「语音输入」走浏览器自带识别。核对对象、日期和错字后保存。保存不自动取得对外分享或执行权，资料需由本人明确选择用于相关事项，再按用途和授权采用。

人物记录保留来源、时间、提供者和更正状态。学习记录与周末安排两个轻量视图演示授权后的最新记录复用；这些是本作品内测试来源，没有读取真实学校软件、微信或手表。

## 与别人办事

模型按各方可用条件提出方案，程序检查授权、预算依据和版本。模型代表审阅与本人接受分开；各参与者必须接受同一版，未回应仍待确认，条件变化使旧接受失效。A／B／C 是三个演示身份，B 小周与 C 小林同户，实际两个家庭；第三家未知就保留缺口，不拿配偶凑数。

限定来宾接单用邀请并自称，补自己的条件和名单；发起人认可后，依全部当前条件重排新版本，再由来宾本人对这一版表态；不继承 B／C 私人资料，代表审阅不计本人接受。资料先关联私有来源，再明确公开选中短字段，更正后重新选择短字段、再次确认公开，按全部当前条件重排并核新版出处。上述流程已在 t27 双浏览器／隔离库的独立范围内通过，仍是有限 guest 演示，不是实名或公网账号系统。

Chrome「随身助手」插件延续本人的购物需求：跨页面查看来源和待确认项、复制需求，在支持的模拟商店预览后代填，并实际读回页面值。应用同一购物事项可查看回执。家庭活动不强行进入购物接口；未适配网页由本人复制需求、手动继续。插件不提交订单、不付款。插件是你在电脑上代替操作页面的那双手，只跑在桌面 Chrome/Edge：加入一次长期有效，重开浏览器、换页面都保持，只有在演示设置里撤销这台设备才失效。Android 的 Chrome 不支持安装扩展，手机不能安装也不能加入；手机和这台电脑连的是同一个助手，手机上交办的事由这台电脑上的插件执行，回执回到同一件事里，手机上能看到的是同一事项的代填回执。

## 边界

文本和明确选择的识别图像会发送到运行者配置的模型服务；采用虚构资料演示。商品、购买、支付和物流均为 `simulated`，没有真实交易或消息发送。当前是局域网 Web 演示，不是公网多用户服务。

服务端 ASR 经 26 次请求实测不可用：模型名路由／上游连通失败，标准音频端点不存在，音频 chat 模型没有产出转写。浏览器 SpeechRecognition 仅已接线，真麦克风待验；不可用时打字或输入法语音转文字后粘贴，后者不算内置识别完成。详见[语音核查摘要](<delivery/verification-summary.md>)。

核心智能环节默认配置为 `step/step-5-preview`，已有范围明确的实际调用证据；不宣称比赛使用率百分比、直接上游身份已完全证明或硬件加分资格。未实现真实电商、外部 Agent 接力、语义检索和公开多用户认证。
