## 第 3 步：三家出游请求与同一事项继续

1. 在对话中原样输入：「周末三家一起带孩子出去玩，我出100以内」。
2. 点 ↑，看回复并点「打开这件事」。
3. 预期：进入家庭活动事项，不追问送礼对象或要求点一个孩子；100 元记为「本人出资上限」，不是活动总预算，也不是付款承诺。
4. 事项应写明目标 3 家、目前候选及确认缺口；已知演示 A／B／C 实为两个家庭，小周与配偶小林同户。第三家未知时保留待确认，不拿配偶凑数。
5. 家庭和孩子按已记录的关系展示。认识两位孩子不等于他们都会来；孩子名单数只表示本人提供的名单条数，不是确认出席人数；逐个记录来、不来或待定，缺的仍未知。不要给其他家庭代填孩子或出席。
6. 当前本人若确有两个孩子，可补「我家2个孩子」；纯演示只能用明确标记的虚构资料。没有记录名字／出席就继续显示缺口，不自动生成孩子。
7. 想邀请小周家时补「小周家和另外一家」，再打开同一事项：小周家为候选，另外一家仍待确认；邀请不等于对方已同意或已参加。
8. 点当前显示的「按当前条件排第一版」。方案应标候选、列出仍缺的条件；未知总额不把各家上限相加。没有其他方确认仍可先提候选，不应显示所有家庭都已约定。
9. 如真实请求失败，记录页面原因；事项和本人条件应保留，按钮恢复后可重试。不要人为断服务或制造付款失败来演示。
10. 成功后点「改我的条件」，只改本人条件，例如时间。保存后需重排；点「按各家当前条件重排」继续，新版本需重新确认，旧接受不能继承。本人「接受这一版」只代表本人；「让代表先看这一版」标模型代表审阅，不冒称别人的点击。

### 3.1 受邀家庭在限定页面参加

1. 发起人在同一事项的「邀请另一个家庭参与」区点「生成单次邀请」，复制这次地址，自己发给参与者；系统不自动发送。手机用电脑当前同网地址，不把 localhost 链接发给另一台手机。
2. 参与者在另一个独立浏览器／设备中打开链接，点「接受这次邀请」，填写自称家庭称呼。演示使用虚构称呼；链接持有者与实名身份不同，不自动登录成既有小周或小林。
3. 来宾只补自己的时间、出资等条件与孩子名单。名单数留空表示未知，0 表示没有孩子；名单数 2、一个来一个待定，不能显示为两人已确认出席。
4. 发起人回同一事项点「认可自称家庭」。若需替换空候选槽，明确选择；只能替换无条件、无决定、无出席的候选，不继承联系人资料。随后按全部当前条件重排出新的可表态版本，不对补条件前的旧版直接接受。接邀请、认可入场、重排、接受方案分别记录。
5. 在新的当前版本上，来宾可点「请代表先审阅」，结果只记代表建议、本人尚未确认；要接受这一版，来宾自己明确点击接受。未回应、缺家庭或出席未确认时，事项仍为候选。
6. 更改条件并重排后，旧接受失效，每方确认当前版本。来宾刷新应恢复同一事项和自己的条件；受限页不应出现私人资料、模型配置、重置、插件或身份切换。
7. 撤回邀请仅在虚构测试邀请上、经本人确认执行；已兑换访问应一并失效，页面留明确失效状态，不跳到发起人普通首页。不要清站点数据来验证权限；本地默认 A 系统没有生产账号保障。

该有限 guest 能力已有 t27 双浏览器／隔离库的独立及限定真实模型输入证据；Android 仍须本次设备操作。原 A／B／C 代表授权保留既有语义，不能把旧代表接受改称各方亲自点击；新 guest 的代表建议不计本人接受。无其他实际协作者时写「未执行」，不让发起人切身份代答。

## 第 4 步：图片识别两步选择并保存

这条是默认流程：先写 → 一级选项点「图片识别」选图 → 图先进草稿（**还没送出去**）→ 弹层内选「识别图里的文字，进正文框」→ 文字进入原正文 → 核对编辑 → 保存。只有点过「识别」那一下才把图送出去；选「只把图存进资料库，不识别」则一次都不送。

### 4.1 打开资料库

1. 点「☰」→「资料库」→「添加资料」。
2. 在「记什么」正文框先打一行，例如「今天的活动记录」。不用先拍照或选人。
3. 「记在谁名下」在保存前补正确对象；「发生日期」指资料发生的日期，不是活动日期。留空表示日期未知。

### 4.2 准备虚构文字图

用纸写「练琴四十分钟」等虚构短句，拍照或使用自己制作的测试图。只用无敏感信息的画面。相册还是拍照由浏览器系统选择器决定，不承诺一定直开相机。

### 4.3 「图片识别」两步

1. 在一级选项点「图片识别」，在系统选择器选图／拍照后返回。
2. 缩略图出现在草稿，弹层内问「这张图要拿来做什么？」，并说明图还没有送出去。
3. 点「识别图里的文字，进正文框」后才显示「正在识别这张图…」。
4. 识别完成后，文字追加在原正文末尾，中间换行；原来手写的内容应仍在。
5. 若点「只把图存进资料库，不识别」：不出现识别过程，弹层内明确写「没有识别图里的字」，正文不被插字。

### 4.4 核对与失败恢复

正文下面的提示行说明每张图识别把握或原因，没有第二个必须编辑的「识别内容」框。直接在同一个正文框改错字。识别可能等待一到数分钟，不以秒回作为通过要求。

失败时应显示具体原因、图片作为配图保留、本人原文不受影响；可手动改正文、重新识别或稍后继续。只有原因提示不等于读图成功。若界面长时间不恢复，截图交实施方，别删资料来掩盖失败。

图片区下方的「先选范围再识别」「撤掉识别文字，只留图」用于重做或改用法，不能撤销此前已经发生的识别。要首次就裁剪或不识别，用第 4.3 步弹层内的「先裁剪再识别」或「只把图存进资料库，不识别」。

### 4.5 编辑后保存与重开

1. 核对正文、对象、发生日期，点「保存资料」。
2. 应提示保存成功，保留本人改过的文本；再次打开记录能看到来源、日期及图片。
3. 内容保存不自动授权对外分享、替他家承诺或购买。

## 第 5 步：先裁剪再识别与只存图不识别

### 5.1 首次只识别指定范围

1. 新建一条资料，一级选项点「图片识别」并选定图，弹层内点「先裁剪再识别」。
2. 进入裁剪后，确认前不应开始识别。用手指拖四角和选框：选区跟手、固定对边、不翻转、不跑出图片。
3. 点「就用这个范围」后才识别选区，文字进入同一正文。若选「用整张」则主动改为整图识别，不再称仅选区。
4. 另开一次该入口，点「取消」：回到新建资料，已有正文／附件草稿不丢，不关闭整个弹层；本次未确认选区不发送识别。可再选图继续。

界面未出现识别等待只能证明可见行为；「确认前 0 次 read／只发送选区」已有[选图前验证摘要](<verification-summary.md>)的电脑侧证据。原历史浏览器探针保留工程原位，不随源码包分发；用户肉眼观察不替代网络层证明，真机触屏与编码仍需本次操作。

### 5.2 只把图存进资料库，不识别

1. 新建资料先输入一行本人文字。
2. 一级选项点「图片识别」，拍／选一张无字要读的测试图。
3. 弹层内点「只把图存进资料库，不识别」。
4. 图片入草稿，弹层内明确反馈「没有识别图里的字」，不出 OCR 等待、正文不被插字；原正文保留。补对象和日期、保存，再开记录确认配图还在。

不要先点「识别图里的文字，进正文框」再点图下「撤掉识别文字，只留图」，然后报告全程没有识别请求；已经送出去那一次不能撤销。

## 第 7 步：资料明确用于家庭事项

1. 保存第 4／5 步的同一条资料后点「用于家庭活动」，不用重新录入或手动复制正文。核对来源、发生日期与字段，初始没有勾选。
2. 选择相关本人未完的家庭活动，或填新标题后「新建家庭活动并关联」。只关联这条真实保存的来源；失败应保留原文、标题和选择，可重试，不出现半个新事项。
3. 第一步点「关联所选资料」后显示「已关联，还未公开」。这是本人私有引用；未选字段、正文、附件不会自动给其他家庭或共同模型。纯配图可只关联来源，不再触发 OCR。
4. 若确需分享具体条件，从已选短字段原值逐项选择公开条件；核对活动日期与资料发生日期不同，勾「我已核对这些值，同意本事项其他家庭可见」，点「确认公开本方条件」。只选正文时不能把全文当时间或地点；可以先回事项点「更正所选字段」补本人核对的具体字段，再重新选择与公开。
5. 在同一事项查看来源区。刚关联只应显示「已关联，尚未被当前共同方案采用」；只有当前共同方案的服务器出处确实引用公开字段，才标「当前版本实际采用的公开条件来源」。保存、关联或显示按钮不等于模型已经采用。

1. 在第 7 步同一家庭事项的本人资料来源区点「更正所选字段」，只更正自己的虚构资料并明确确认。

## 出问题怎么办

| 现象 | 处理 |
|---|---|
| 手机打不开 | 检查当前二维码、HTTP／端口、同网及访客隔离；电脑打不开时交实施方，不让用户部署服务 |
| 地址变了 | 电脑「在手机上打开」重新取，不照抄旧截图 |
| 无法安装到主屏幕 | 记录浏览器限制，继续网页；安装结果单列 |
| 识别长时间不结束 | 记录耗时、状态、提示，保留原文与草稿；实施方核查，不自动当已识别 |
| 字不对 | 在正文核对改正后保存，记录实际错误；不把结果空白当读图通过 |
| 语音不支持 | 记录限制，可试输入法；不放宽浏览器安全规则，不声称ASR通过 |
| 事项按钮无响应 | 记标题、按钮、版本和截图，交实施方；不删历史掩盖 |
